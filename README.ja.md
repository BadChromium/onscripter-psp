# ONScripter PSP

[English](README.md) | [简体中文](README.zh-CN.md) | 日本語

PSP 向けの ONScripter 開発プロジェクトです。PSP 本来の **480×272** 表示と、**480×270（270p）** のゲームへの対応を目指しています。最初のソーススナップショットは Biman 移植プロジェクトに由来します。本リポジトリにはエンジン、依存ライブラリへのローカル修正、回帰テストが含まれますが、**ゲーム本体は含まれません**。シナリオ、画像、音声、フォント、セーブデータ、ISO も含まれません。

## 開発状況と貢献

**開発初期のスナップショットであり、任意のゲームにそのまま使える汎用エンジンではありません。** スクリプトの論理解像度は `;$V4000G1500S480,272` や `;$V4000G1500S480,270` などのヘッダーから読み取ります。480×270 のヘッダー解析にはホスト側の回帰テストがありますが、PSP 実機での表示位置や描画については、別途検証が必要です。

本プロジェクトは、開発、デバッグ、テスト、ドキュメント作成に**生成 AI（GenAI）を使用しています**。生成されたコードには誤りが含まれる可能性があります。Issue、コードレビュー、修正、テスト、ドキュメント、Pull Request を通じた改善を、どなたからも歓迎します。報告には再現手順を添え、PSP 実機での結果とエミュレーターでの結果を区別してください。

再利用可能な補助モジュールには、機能に応じた名前を付けています。`PSPSavedata.h`（保存先の振り分けとエラーチェック付き書き込み）、`PSPSavedataDescription.h`（SFO の説明文更新）、`ONSSaveText.h`（テキスト変換）、`PSPSavedataMac.h`（mode-1 整合性検証）、`ONSMaskGain.h`（マスクを用いた画面遷移）です。いずれも不要なゲーム素材ではありません。

ゲームごとに固有の識別子を指定してビルドしてください。例：`make -f Makefile.PSP GAME_ID=TEST00001 PSP_EBOOT_TITLE="My Game"`。識別子は大文字の英字 4 文字と数字 5 桁で構成します。ここでの `ONSP00001` はエンジン開発用です。配布する複数のゲームで共用しないでください。識別子や文字コードを変更する前には `make -f Makefile.PSP clean` を実行してください。コンパイラーオプションの変更は make の依存関係として追跡されません。

汎用化は未完了です。現在のセーブデータアダプターは 8 スロットに対応し、それぞれに合った `ui/savedata/{CFG,01..08}.SFO` テンプレートと、`ICON_SYSTEM.PNG`、`ICON0.PNG`、`PIC1.PNG` が必要です。説明文の更新処理は、従来の固定 SFO レイアウトを前提としています。GAME_ID を変更しても、これらのテンプレートは生成・更新されません。テンプレート内のセーブディレクトリ識別子を、ビルド設定と一致させる必要があります。既定の文字コードは引き続き CP936（`ONS_CN_CP936`）です。汎用的なメタデータ生成や、より多くのセーブスロットへの対応は今後の課題です。移植元プロジェクトで動作確認済みのゲーム配布物は変更していません。

## 主な変更点

- ネイティブ 480×272 のスクリプトレイアウトと CP936 テキストへの対応。
- PSP PMF 再生と GPU 統合、音声バッファーのライフサイクル改善、背景キャッシュ。
- ゲーム識別子を設定できる PSP セーブデータ処理、会話操作、診断ログ。
- ディスク起動時の作業ディレクトリは `disc0:/PSP_GAME/USRDIR`。診断ログは `ms0:/PSP/<GAME_ID>_ISO.log` に出力。

ソースには、実機テスト済みビルドの診断機能が残されています。PSP03g、6.20 PRO-C2 / Inferno の環境で、起動、同一起動中のロード、ゲーム再起動後のロードが動作したとの報告があります。これは、すべての PSP での動作保証や、実機での全編通しプレイの確認を意味しません。ビルドは拡張メモリーを要求するため、現時点で PSP-1000 は対応対象外です。

## ビルド

PSPSDK、PSP SDL 1.2 と、その画像・ミキサー・フォント関連の依存ライブラリが必要です。以下の固定バージョンの PSPDEV コンテナーを検証済み環境として使用しています。Linux シェルでリポジトリのディレクトリに移動し、実行してください。リポジトリをマウント済みドライブに置いた WSL 環境でも実行できます。

```sh
docker run --rm -v "$PWD:/src" -w /src \
  pspdev/pspdev@sha256:b22811072ea0721d7f6c666a5a279b6def2b0cd95892b819d9570f8ffc4452c0 \
  sh -c 'make -f Makefile.PSP -j4'
```

生成物は `EBOOT.PBP` と `onscripter.elf` です。PBP には開発用の基本的なメタデータのみが入り、ゲーム画像は含まれません。合法的に入手した互換性のあるゲームデータを別途用意してください。本リポジトリだけで、配布済みのゲーム ISO を再生成することはできません。Makefile は、同梱された依存ライブラリの修正版をソースからビルドします。

ビルド後は `python -m unittest discover -s tests` を実行してください。テストには Python 3 が必要です。ホスト側でコンパイルするテストプログラムには、それぞれ指定のホストコンパイラーも必要で、一部は Windows Visual Studio 2022 Community を使用します。CP936 のテスト入力は生成したもので、ゲームからコピーしたものではありません。非公開の作業環境に依存するインポート修正テストは含めていません。実機テストは、このテストスイートとは別に行う必要があります。

ディスクのパッケージングには、動作確認済みのゲームで `genisoimage -xa -iso-level 3 -allow-lowercase -allow-multidot -omit-version-number` を使用しました。XA でないイメージでは、テストした PSP で一部のファイルを開けない問題が発生しました。エンジンが直接開く動画や補助ファイルは、NSA アーカイブの外に置いてください。
